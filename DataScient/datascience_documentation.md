# FinanceAI Data Science Documentation

This document provides a comprehensive technical overview of the Data Science component of FinanceAI, located at `C:\Java\G9-LATAM-Team-77\DataScient`.

## 1. File Structure and Components

- **`src/predict.py`**: The core inference engine that handles predictions via a CLI/subprocess JSON protocol. It supports three types of predictions: transaction classification, profile risk scoring, and full financial analysis.
- **`src/train_models.py`**: The training pipeline for the machine learning models. It trains both the transaction classification model (Logistic Regression) and the profile classification model (Random Forest).
- **`requirements.txt`**: Specifies the virtual environment dependencies (e.g., `pandas==3.0.5`, `scikit-learn==1.9.0`, `joblib==1.5.3`, `numpy==2.5.1`).
- **`models/*.pkl`**: Serialized ML model artifacts (`transaction_model.pkl` and `profile_model.pkl`) generated by the training pipeline.
- **`data/processed/*.csv`**: Datasets used for training (`dataset_clasificacion_transacciones.csv` and `dataset_perfiles_financieros.csv`).

## 2. Machine Learning Architecture

### 2.1 Problem Formulation
The system addresses two main predictive tasks:
1.  **Transaction Classification**: A natural language processing (NLP) task to classify free-text transaction descriptions into predefined categories (e.g., "Alimentación", "Transporte").
2.  **Financial Health Scoring (Overspending Risk Classification)**: A tabular classification task that evaluates a user's financial variables to predict their financial profile: "Saludable", "En observación" (or "Riesgo"), or "En riesgo" (or "Crítico").

### 2.2 Mathematical Formulation of Dimensionless Ratios
The engine relies heavily on engineered dimensionless ratios to evaluate financial health. Key formulations include:
-   **`ratio_gastos_ingresos` (Expense-to-Income Ratio)**:
    $$ \text{Ratio} = \frac{\text{Total Gastos}}{\text{Ingreso Mensual}} $$
-   **`tasa_ahorro_pct` (Savings Rate)**:
    $$ \text{Ahorro Ratio} = \frac{\max(0, \text{Ingreso Mensual} - \text{Total Gastos})}{\text{Ingreso Mensual}} $$
-   **`endeudamiento_ratio` (Debt-to-Income Ratio)**:
    $$ \text{Ratio} = \frac{\text{Deuda Total Mensual}}{\text{Ingreso Mensual}} $$
-   **Category Distribution Weights**:
    -   `porcentaje_gasto_esencial` = Gastos Básicos / Ingreso Mensual
    -   `porcentaje_gasto_discrecional` = Gastos de Estilo de Vida / Ingreso Mensual

**Multi-Currency Neutrality**:
By transforming raw monetary values (USD, MXN, EUR, COP, etc.) into dimensionless ratios (percentages or fractions), the models achieve multi-currency neutrality. Since the numerator and denominator of every ratio are in the same currency, the monetary unit cancels out. A 30% debt-to-income ratio indicates the same relative financial strain regardless of whether the income is 1,000 USD or 20,000 MXN.

### 2.3 Training Pipeline
The training pipeline (`train_models.py`) encompasses:
-   **Preprocessing**:
    -   *Transactions*: Drops null descriptions, applies `TfidfVectorizer(max_features=5000)` to extract text features.
    -   *Profiles*: Drops missing values across key financial ratios (`ingreso_mensual_usd`, `nivel_endeudamiento`, `ratio_gastos_ingresos`, etc.).
-   **Modeling**:
    -   *Transactions*: Logistic Regression (`max_iter=1000`).
    -   *Profiles*: Random Forest Classifier (`n_estimators=100`) which inherently captures non-linear relationships and feature importance.
-   **Cross-Validation & Metrics**: Uses a standard 80/20 train-test split (`train_test_split`) evaluated via classification accuracy on the test set.

### 2.4 Inference CLI / Subprocess Pipeline
The backend (Spring Boot) communicates with the Python engine via a CLI interface defined in `predict.py`.
-   **Protocol**: It reads a JSON payload either from `sys.argv` arguments or standard input (`sys.stdin`) and outputs a JSON response to standard output (`sys.stdout`).
-   **Types of Analysis**: Controlled by the `"type"` field in the JSON request (`"transaction"`, `"profile"`, `"full_analysis"`).

### 2.5 Error Handling and Fallback Mechanisms
The inference engine is designed to be highly fault-tolerant:
-   **Missing Model Fallbacks**: If `profile_model.pkl` is absent, the system gracefully falls back to a deterministic, rule-based heuristic matrix to classify the profile based on hardcoded thresholds (e.g., Debt > 50% = "En riesgo"). If the transaction model is missing, it falls back to a predefined dictionary mapping (`SUBCATEGORIA_A_CATEGORIA`).
-   **Zero Income / Empty History**: To prevent `ZeroDivisionError`, income variables are checked (`if ingreso_mensual > 0`). If income is zero, ratios are capped or assigned default worst-case values (e.g., `ratio_gastos_ingresos` = 1.0 or 2.0). Missing numerical inputs are safely parsed using a `_safe_float` utility function defaulting to `0.0`.
